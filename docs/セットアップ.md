# Google接続とCloudflareのセットアップ

対象: v0.2.0 / 作成日: 2026-10-29

サンプル画面はこれまでどおり使えます。実際の登録チャンネルを取得するには、最初に以下のGoogle設定が必要です。
秘密情報の実値はチャットやGitへ貼り付けず、手元の設定ファイル・Cloudflare Secretsへ入力してください。

## 1. Google Cloudを準備する

1. [Google Cloud Console](https://console.cloud.google.com/) で、このアプリ用のプロジェクトを作成または選択します。
2. 「APIとサービス」のライブラリで **YouTube Data API v3** を有効にします。
3. 「Google Auth Platform」（またはOAuth同意画面）を開き、アプリ名・連絡先を設定します。
4. 個人Googleアカウントの場合は、対象ユーザーをExternal、公開状態をTestingにし、テストユーザーに自分のGoogleメールアドレスを追加します。
5. データアクセスのスコープに次を設定します。YouTubeの書き込み権限は不要です。

```text
openid
email
https://www.googleapis.com/auth/youtube.readonly
```

画面の名称はGoogle側の更新で変わる場合があります。[Webサーバー向けOAuth公式手順](https://developers.google.com/identity/protocols/oauth2/web-server) も参照してください。

## 2. OAuthクライアントを作る

1. Google Auth Platformの「クライアント」から、種類を **ウェブアプリケーション** にして作成します。
2. ローカル開発では次のURIを設定します。

| 項目 | 値 |
| --- | --- |
| 承認済みJavaScript生成元（設定する場合） | `http://127.0.0.1:5173` |
| 承認済みリダイレクトURI | `http://127.0.0.1:5173/auth/callback` |

3. 発行されたClient IDとClient Secretを手元へ控えます。

リダイレクト先はフロントエンドの5173番です。内部的にバックエンドの8787番へ転送します。
`localhost` と `127.0.0.1` は混在させないでください。使う場合はAPP_ORIGINとGoogle側の登録URIを同じ値へ揃えます。
この実装は各YouTube APIへOAuthトークンを付けてリクエストするため、別のYouTube APIキーは不要です。

## 3. ローカルの秘密情報を設定する

プロジェクトのターミナルで実行します。

```powershell
npm.cmd install
npm.cmd run secrets:init
```

`.dev.vars` が作成されます。暗号鍵はランダムに生成され、画面には出ません。既存ファイルがある場合は上書きしません。
このファイルを手元のエディターで開き、次の項目を設定します。

| 項目 | 設定内容 |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Googleで発行したWebクライアントID |
| `GOOGLE_CLIENT_SECRET` | 同じクライアントのSecret |
| `TOKEN_ENCRYPTION_KEY` | 自動生成済みの値を維持 |
| `ALLOWED_GOOGLE_EMAIL` | 自分が接続するGoogleメールアドレス |
| `ALLOWED_GOOGLE_SUB` | 初回は空欄でよい |

初回はGoogleが確認したメールアドレスで許可対象を確認し、そのアカウントの不変識別子 `sub` をD1へ固定します。
その後は、メールだけが同じ別アカウントへの置き換えを拒否します。所有者を変える操作は自動で行いません。
既に `sub` が分かっている場合は `ALLOWED_GOOGLE_SUB` を指定でき、こちらを優先します。

`TOKEN_ENCRYPTION_KEY` は保存済みトークンを復号する鍵です。安易に変更・削除しないでください。
変更した場合は再接続が必要です。

## 4. データベースとアプリを起動する

ローカルD1にテーブルを作ります。同じマイグレーションを繰り返し実行しても適用済みのものは再実行されません。

```powershell
npm.cmd run db:migrate
```

ターミナルを2つ使います。

```powershell
# ターミナル1: バックエンド
npm.cmd run worker:dev
```

```powershell
# ターミナル2: 画面
npm.cmd run dev
```

1. 通常のChrome・Edge・Safariで [ローカルアプリ](http://127.0.0.1:5173/) を開きます。Google認証にはアプリ内蔵ブラウザを使用しません。[GoogleのOAuthポリシー](https://developers.google.com/identity/protocols/oauth2/policies#use-secure-browsers) で、埋め込みブラウザでの認証が制限されているためです。
2. 歯車の設定から「接続状態を再確認」を押します。
3. 未設定の表示が消えたら「Googleアカウントに接続」を押し、自分のアカウントで読み取り権限を許可します。
4. アプリへ戻ったら更新ボタンを押します。初回は登録チャンネルと各チャンネルの過去分を取得します。
5. 以後の通常更新は、前回成功した更新の開始日時以降を中心に取得します。

`.dev.vars` を変更して反映されない場合は、バックエンドを `Ctrl+C` で停止して起動し直します。
既に同じポートのサーバーが動いている場合は重複起動せず、既存のものを使用または停止してください。

## 5. 日付による差分更新

- 更新を開始した日時を基準候補とし、全チャンネルの処理が成功したときだけ確定します。
- 完了日時を基準にすると、同期中に公開された動画を取りこぼす可能性があるため使いません。
- 基準日時はD1を正とし、成功結果をブラウザにも保存します。ブラウザの日時改変や端末変更で取得範囲を飛ばしません。
- 通常投稿は新しい順に取得でき、過去日付で新規動画が追加されない前提です。
- APIの一覧には日付指定パラメーターがないため、新しいページから確認して基準日時より古い動画で打ち切ります。
- 境界の遅延に備えて初期値10分を重複確認し、動画IDで重複保存を防ぎます。
- 初回・新規登録チャンネル・「登録チャンネルと過去分を再取得」は、初期値で各チャンネル100本まで確認します。
- 通常更新では初回取得の本数制限を使わず、前回日時へ達するまで必要なページを確認します。
- 既存メタデータの公開状態などは、保存期限に合わせて別途再確認します。

設定値は `wrangler.jsonc` の該当環境の `vars` にあります。

| 設定 | 初期値 | 意味 |
| --- | ---: | --- |
| `UPLOAD_PAGES_PER_CHANNEL` | 2 | 初回・過去分再取得のページ数。1ページ最大50本 |
| `SYNC_OVERLAP_SECONDS` | 600 | 基準日時の前後で重複確認する時間のうち、前へ戻す秒数 |
| `CATALOG_LIMIT` | 1000 | 画面へ渡す新しい動画の最大件数 |

表示対象は公開・埋め込み可能な登録チャンネル動画です。配信予定動画、非公開・削除・埋め込み不可の動画は通常一覧に出しません。

## 6. 接続期限・エラー

- [Google公式仕様](https://developers.google.com/identity/protocols/oauth2#expiration) では、External/Testingのアプリに発行されるリフレッシュトークンは、今回のスコープ構成では通常7日で期限切れになります。期限切れ時は設定から再接続します。
- アプリのセッションは30日間です。Google権限の取り消し、暗号鍵変更、Cookieの削除などでも再接続が必要になる場合があります。
- `redirect_uri_mismatch`: Googleの登録URIとAPP_ORIGIN・アクセス先を確認します。
- `accessNotConfigured` 相当の案内: 対象プロジェクトのYouTube Data API v3を有効にします。
- 利用上限: 時間をおいて再試行します。失敗で基準日時や取得済みデータを空にしません。
- 中断・通信失敗: 更新ボタンを再度押すと、1時間以内なら保存済みの処理位置から再開します。
- チャンネルの投稿一覧が見つからない・アクセスできない・一時的に取得できない場合は、そのチャンネルを飛ばして続行します。取得できた動画を表示し、一覧と設定の「チャンネル名と取得できなかった理由」で対象とHTTP番号・既知のAPI理由を確認できます。
- 一部失敗時は全体の基準日時を維持します。「更新を再試行」または通常更新で再確認できます。完了した同期の警告は、同期ジョブが残っている1時間以内は再読み込み後も確認できます。過去分再取得の失敗対象も、この間は次回の通常更新で過去分を再確認します。
- 認証切れ・読み取り権限不足・API利用上限では後続も成功しないため、全体を中断します。中断しても、それまでに取得した動画を一覧へ反映します。
- ログアウト: 現在のセッションだけを終了します。
- 接続解除: Google側の権限失効を試み、D1の動画・チャンネル・トークン・セッションを削除します。所有者固定用の識別子は設定として残ります。
- Google側の権限解除に失敗した場合は、[Googleアカウントの接続管理](https://myaccount.google.com/connections) でも確認してください。

## 7. Cloudflareへ配備する場合

以下はユーザーが配備するときの手順です。この作業ではリモートDB作成、Secrets登録、公開デプロイは行っていません。

1. Cloudflareアカウントを準備し、ターミナルでログインします。

```powershell
npx wrangler login
npx wrangler d1 create youtube-kit
```

2. 返されたD1のIDを、`wrangler.jsonc` の **env.production.d1_databases** の `database_id` へ設定します。全ゼロのIDはローカル用の仮値です。
3. **env.production.vars.APP_ORIGIN** を実際に使用するHTTPSのWorkers URLへ設定します。初期値の `.invalid` URLでは認証を受け付けません。
4. **env.production.vars.ALLOWED_GOOGLE_EMAIL** または **ALLOWED_GOOGLE_SUB** を設定します。許可対象の識別子であり、Client Secretとは区別しています。`ALLOW_DEMO` は本番ではfalseを維持します。
5. ローカル用と同じ手順で作った本番用OAuthクライアントへ、HTTPSの `/auth/callback` URIを登録します。Google側のアプリのホームページは本番トップ、プライバシーポリシーは本番の `/privacy.html` を使用できます。
6. 本番の秘密情報を対話入力で設定します。コマンドの引数へ秘密値を直接書きません。

```powershell
npx wrangler secret put GOOGLE_CLIENT_ID --env production
npx wrangler secret put GOOGLE_CLIENT_SECRET --env production
npx wrangler secret put TOKEN_ENCRYPTION_KEY --env production
```

本番の暗号鍵も32バイトのランダム値をBase64形式にします。ローカルで作った鍵を使う場合は手元の `.dev.vars` から対話入力へ移し、ファイル自体は配布しません。
Google側でTestingから公開状態を変更する場合は、表示される確認・審査・スコープの要件を確認して進めてください。

7. 本番D1へマイグレーションを適用し、事前確認後に配備します。

```powershell
npx wrangler d1 migrations apply DB --remote --env production
npm.cmd run build
npm.cmd run worker:check
npm.cmd run worker:dry-run -- --env production
npx wrangler deploy --env production
```

D1のローカルと本番は別です。ローカルの認証情報・Cookie・保存キューは自動移行しません。
古いAPIメタデータと期限切れセッションを整理する日次処理も設定しています。クラウド上での実行確認は配備後の確認項目です。
費用・クォータは利用するCloudflare/Googleアカウントの現行条件を確認してください。

## 8. 今回の検証範囲と次の段階

- フロントエンドとWorkersの型検査、ビルド、D1マイグレーション、Workersドライランを実施しました。
- 認証・署名・権限・CSRF・差分同期・再開は、ローカルの実WorkersランタイムとD1を使い、Google応答をテスト用に置き換えて検証しています。
- 実Googleアカウントの同意・登録チャンネル取得、Cloudflare本番、iPhone Safariは未検証です。
- キュー・非表示・表示設定は、サンプルとアカウントごとに分離したブラウザ内保存です。端末間同期はまだ行いません。
- 画面へ読み込む件数上限を超えた動画や取得範囲外の動画は、保存済みキューにIDだけ残って再生を開始できない場合があります。IDを無断で消さず、利用者に確認を促します。
- Manifest、Service Worker、アプリ本体更新、キューのサーバー同期は次の段階です。
