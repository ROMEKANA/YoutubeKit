# 一人用クラウド保存・ブラウザ間同期（v1.2.0）

設計・実装日: 2026-11-04

## 保存先と認証

既存のWorkersとD1を使う。許可済みGoogleアカウントのセッションだけが読み書きでき、変更APIには同一OriginとCSRFトークンを要求する。追加のGoogle権限やサービスへの登録は不要。動画・音声、認証トークンは同期データに含めない。サンプルモードは同期しない。

## 同期するデータ

| 対象 | 統合・保存方法 |
|---|---|
| 名前付き保存キュー | UUIDが未登録なら追加。同じIDを二重保存せず、名前・内容も上書きしない。別IDは同じ名前・内容でも残す。全ブラウザの一覧はサーバーへの保存順を共有する |
| 保存キュー削除 | 削除済みIDを残し、古いブラウザからの復活を拒否。復元は新しいUUIDで保存 |
| 非表示・復元 | 動画ID単位の真偽値として同期 |
| 再生位置 | 動画ID単位で同期。秒数の最大値ではなく版番号で競合を検出し、巻き戻し・ゼロも扱う |
| 共通設定 | 項目ごとに同期。視聴割合、一覧件数、短い動画の除外、再開設定、ローカル保存間隔など |
| 現在のキュー・再開動画 | ブラウザIDごとにクラウド保存。別ブラウザの操作で自動置換しない |
| 表示密度・シアターの明るさ・最大化 | ブラウザごとに保持。バックアップには含む |
| 自動同期の有効状態・送信/確認間隔 | ブラウザ専用の設定。バックアップ復元でも変更しない |

再生セッションがある間はクラウドの再生位置を画面の状態へ適用しない。現在の再生キューも維持する。受信した位置は次の同期で、再生セッションを終了してから適用する。

新規ブラウザに現在のキューがなく、自分のクラウド保存もない場合は、他ブラウザの最後に保存されたキューを復元する。既存ブラウザは設定の「別ブラウザのキューを引き継ぐ」で明示的に切り替える。引き継ぎとバックアップ復元は再生セッション中には実行できない。

## 自動処理と設定

- 自動同期の初期値はオン。起動・ログイン、画面へ戻ったとき、通信復旧時に同期する。
- 保存キュー・非表示・共通設定・現在のキューの変更は約2秒後にまとめて送信する。
- 再生位置の定期送信は初期30秒、他ブラウザの定期確認は初期60秒。
- どちらの間隔もオフ・15・30・60・120・300・600秒から選べる。
- 再生位置の定期送信をオフにすると、位置の通常同期は「今すぐ同期」で送信する。復旧用の全状態バックアップには位置も含まれる。
- 定期確認をオフにしても、起動・復帰・操作内容の送信時には他ブラウザの変更を取得する。
- 自動同期全体をオフにすると、自動の送信・確認・バックアップを止める。ローカル保存は継続し、手動同期・バックアップの閲覧・復元は使える。
- 表示中だけ定期処理する。閉じたアプリやバックグラウンドでの定期動作は保証しない。
- ローカル保存の間隔と通信間隔は独立している。ローカルでまだ記録されていない位置は送信しない。

## 通信失敗・競合

未送信の項目と、その編集元のサーバー版番号をlocalStorageへ保存する。通信できなくてもローカル操作を続け、次の同期機会に再送する。自動同期を止めた状態でも未送信操作は保持する。サイトデータ削除で未送信分は失われるため、削除前には手動同期を行う。

サーバーはSQLの条件に版番号を含める。古い版からの同一項目の変更は採用せず、サーバー確定済み値を優先する。再送した同じ値は重複更新しない。通信中に編集された項目は受信で置換しない。競合したローカル値はブラウザへ退避し、その状態を次の同期でバックアップへ送信する。競合件数は同期状態欄へ表示する。

同期状態欄は設定画面に置き、「同期中」「同期済み」「未送信あり」「同期失敗」を表示する。同期に失敗してもローカルのキューや設定を消さない。

## バックアップと復元

- 初回のクラウド同期前、保存キュー削除前、バックアップ復元前の状態を退避する。
- 各ブラウザで、その日の最初の同期前の状態を一日一世代保存する。日付は日本時間。アプリを使用しない日は作成しない。
- 日次分と削除前などの退避を合計して、ブラウザごとに直近30世代をD1へ保持する。
- 設定の「バックアップから復元」で日時とブラウザIDの先頭を確認し、確認ダイアログから復元する。一覧は全ブラウザの最新100件。
- 復元は現在のキュー・保存キュー一覧・非表示・再生位置・表示設定を選んだ世代へ戻す。変更は次の同期で他ブラウザへ伝える。削除済みキューを戻す場合は新しいUUIDを割り当てる。
- 自動同期がオフなら復元後も自動送信しない。「今すぐ同期」で送信する。

バックアップも同じD1に保存するため、Cloudflareアカウントやデータベースそのものを失った場合の独立した外部バックアップではない。

## 実装構成と制約

- `cloud_entries`: アカウント・項目キー・JSON値・版番号・サーバー更新時刻。削除済みキューの行を残す。
- `cloud_backups`: ブラウザ別の復元用全状態。日次・退避イベントIDで重複作成を防ぐ。
- `/api/cloud/state`: ページ取得と項目単位の条件付き更新。
- `/api/cloud/backups`: バックアップ作成・一覧・個別取得。
- API本文は最大1MiB。単一同期項目はJSON文字列20万文字、バックアップは正規化後50万文字まで。超過時は失敗を表示し、ローカルデータを維持する。
- 定期確認は全項目を200件ずつ取得する方式。利用量が増えた場合は設定で確認間隔を延ばすかオフにできる。差分取得への最適化は今後の対象。
- 同じブラウザの複数タブは同じブラウザID・保存領域を共有する。同時編集より、一つのタブで使うことを推奨する。

## 確認範囲

2026-11-04にフロント・Workerの型検査、ビルド、差分確認が成功した。状態統合2件と同期API3件、計5件の対象テストが成功した。既存の対象外テスト38件は実行していない。APIテストは実アカウントを使わないローカルWorkerで、認証・CSRF・再送・削除済みID・版番号競合・バックアップ取得を確認した。テスト用のローカル通信には実行環境の制限解除が必要だった。

本番D1へ `0003_cloud_state.sql` を適用し、v1.2.0を公開した。公開ページとService Workerが新版を返すこと、未ログイン時に同期状態とバックアップのAPIが401で拒否することを確認した。

実Googleアカウントを使った複数ブラウザ間同期、iPhone Safari/PWA、通信切断後の再送、バックアップからの画面操作による復元は手動確認が必要。

1. PCで保存キューを作成し「今すぐ同期」。別ブラウザで同じアカウントへ接続し、一件だけ表示されることを確認。
2. 別ブラウザで削除・同期し、元のブラウザで同期して復活しないことを確認。
3. 送信間隔・定期確認をオフにして、手動同期で反映されることを確認。全体オフでは起動・復帰でも自動通信しないことを確認。
4. 再生中に別ブラウザでキューを変えても、再生順・位置が変わらないことを確認。
5. バックアップ一覧から削除前を選び、確認後に保存キューを復元できることを確認。
