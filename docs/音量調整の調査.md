# Issue #19 音量調整の調査と実機比較

2026-11-17 / v1.2.23。iPhone中心に、物理ボタンの刻みの粗さ・小音量・調整範囲の不満を改善することが目的。1%刻み自体は必須ではない。

## 調査結果

| 方法 | 判断 |
| --- | --- |
| YouTube IFrame API `setVolume` | 0〜100の指定が公式に提供される。iOSで実音量が変わる保証はない。再生中・停止中・ミュート中の3条件を比較する。返値だけでは成功としない。 |
| コントロールセンターのスライダー | Apple公式の端末音量操作。物理ボタンより希望の音量へ近づけるか実機で比較する。アプリ独立ではなく、最大音量も拡張しない。 |
| ショートカットの「音量を設定」 | メディア音量を数値で指定する候補。1・2・3・5・10%などで最小音量と刻みを比較する。端末共通で、アプリ切替や再開が必要になる可能性がある。アクションはユーザーがiPhone上で作成する。 |
| Web Audio / GainNode | 自前の音源では減衰・増幅できるが、YouTube iframe内の音声を接続する公開APIがない。別オリジンの内部DOMを取得できず、CORSの許可がないメディアのWeb Audio出力も無音となる。YouTubeKitに適用可能な方式とは扱わない。 |
| 過去のネイティブ実装 | `nicokla/volumeYoutubeIosOk`はUIWebViewの通知から内部AVPlayerをKVCで取得しvolumeを書き換える。PWAへ移植できず、本プロジェクトの非公開API非依存方針にも適合しない。コードは転用していない。 |
| YouTube「一定音量」 | 動画の音量変化を抑える機能。独立した倍率指定ではなく、埋め込みでの提供・操作も保証しない。 |

公開APIの100%を超える増幅や、iPhoneのハードウェア出力上限の拡張を提供する方法は今回の調査では確認できていない。

## 比較画面

- 設定の「音量の比較画面」、または `/?lab=volume`。
- 本体Playerに組み込む前の最小構成のYouTubeプレーヤー。標準操作を表示し、自動再生・ループは行わない。
- 準備時はAPI音量100%。1〜100のスライダーと1・5・10・20・50・100のボタンを用意。診断の指定値は通常設定に保存せず、再準備で100%へ戻す。
- 実機情報・出力先・Safari/PWA・動画ID・選択方式・要求音量・API返値・操作履歴・聞こえ方を記録する。履歴は直近120件。
- 記録ボタンで `youtubekit.volume-diagnostic-report` に保存。クラウドには送信しない。保存失敗時はコピーを案内する。過去の記録は明示操作で読み込む。
- 既存の表示ずれ比較画面、通常Player、通常設定、キュー、再生位置、クラウド同期は変更しない。

## 実機での手順と判定

1. アプリをv1.2.23へ更新して比較画面を開く。端末音量を小さくし、機種・iOS版・スピーカー/イヤホンを記入する。
2. 普段聴く動画のURLまたはIDで準備し、動画内の再生ボタンを押す。広告中は判定しない。同じ箇所をシークして比較する。
3. A：端末音量を固定し100→20→5%を比較。必要なら1・10・50%も試す。
4. B：一時停止→停止確認→指定値変更→再開。C：ミュート→無音確認→指定値変更→ミュート解除。前の条件の停止・ミュートは明示的に解除する。
5. D・E：API音量100%・ミュート解除で、コントロールセンターまたはショートカットによる端末音量を比較する。指定値と変化をメモし、検証後は端末音量を戻す。
6. 条件ごとに聞こえ方を記録する。Safari・ホーム画面PWAと、普段の出力先を分ける。「結果をコピー」でチャットへ貼る。

期待結果は、隣り合う物理ボタン段階の間の音量や、従来の最小より小さい可聴音量を作れること。APIの数値変化、ミュート成功、自前の音源の成功はYouTubeの実音量調整成功とは区別する。音声の自動測定は行わない。

実機での実結果：未確認。通常画面への採用・既定値の永続化は、聞こえ方と操作性の結果を受けて決める。Issueは進行中を維持する。
