# 初期試作・技術検証レポート

- 日付: 2026-10-29
- 対象バージョン: 0.1.0
- 対象範囲: フロントエンドの操作試作と公式IFrame Player APIの有限キュー

## 設計

- 一覧には通常の `img` 要素でサムネイルを表示し、サムネイルの操作でキューへ追加する。
- サンプルデータはローカルJSONで、画像だけをYouTubeの公開サムネイルURLから取得する。
- 個人の登録チャンネルやアカウント情報はまだ取得しない。
- 保存はブラウザ内の `localStorage` に限定する。本番D1での端末間同期とは別の段階とする。
- 再生開始時のキューをコピーし、再生途中の保存状態と分離する。
- 再生画面に公式プレーヤーを1つ作成し、動画ID配列を `loadPlaylist()` に渡す。
- `setLoop(false)` でループを無効化する。
- 次動画への遷移はプレーヤーに任せ、`ENDED` イベントから `nextVideo()` を呼ばない。公式プレーヤーの遷移と二重に進むことを避ける。
- 最終項目の再生後に終了イベントを受けた場合だけ、キュー完了として扱う。
- エラー動画の自動スキップは追加していない。エラーを表示して利用者へ判断を返す。
- ページ非表示時は一時停止し、バックグラウンド再生を提供しない。
- 最小構成の検証画面は `/?lab` に分離した。検証用シーク以外は通常再生画面と同じ制御を使用する。

## 公式資料の確認

確認日は2026-10-29。以下は今回採用した機能の範囲での確認であり、全要件の調査完了を示すものではない。

- [YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference): 動画ID配列によるプレイリスト、状態イベント、自動再生阻止、エラー、最小プレーヤーサイズを確認した。プレーヤーには `origin` と `playsinline` を指定する。高さは200px未満にならないようにした。
- [YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies): プレーヤーの標準機能を妨げる変更、広告遮断、動画・音声の分離、非表示のプレーヤーによるバックグラウンド再生を行わない方針とした。
- [Vite公式ガイド](https://vite.dev/guide/): 現行のNode.js要件を確認し、利用環境のNode.js 24でビルドした。
- [Unwatched](https://github.com/fer0n/Unwatched): READMEから有限キュー、受信一覧からの選別、ネイティブアプリである点とGPL-3.0表記を確認した。コードはコピーしていない。内部の再生実装、Shorts判定、PiPの詳細調査は未実施。
- [Cosmos Laundromat公式公開動画](https://www.youtube.com/watch?v=Y-rmzh0PI3c): 試作サンプルに使用する動画IDを確認した。

## 実機での確認手順

起動・アクセス方法はREADMEを参照する。PWAやOAuthの正式確認時にはHTTPS環境を用意する。

1. サムネイルから2本をキューへ追加し、意図せず再生が始まらないことを確認する。
2. 順序変更、個別削除、非表示・再表示、再読み込み後の保存状態を確認する。
3. 通常再生で動画AからBへの遷移と、Bの最終停止を確認する。
4. `/?lab` の終了10秒前へのシークでも同じ結果になるか確認する。
5. 自動再生が阻止されたら、再開操作で同じ動画から再開できるか確認する。
6. 画面ロック・別アプリへの移動・PiPを試し、実際の挙動を記録する。継続再生できるとは想定しない。
7. iOS版、端末名、Safariかホーム画面起動か、発生時刻、表示エラー番号、発生した動画IDを記録する。

トークン、Cookie、Googleアカウント情報などの秘密情報を記録へ含めない。
