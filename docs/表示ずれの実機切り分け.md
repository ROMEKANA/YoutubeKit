# 横画面の映像ずれ：実機での切り分け

作成日: 2026-11-05 / 対象版: v1.2.3

## 症状と環境

利用者から、iPhone 16e・iOS 26.7.1の通常Safariとホーム画面PWAの両方で、縦表示は正常だが、横表示では通常表示・動画最大のどちらでも映像が右へ寄り、左に黒い空き、右端に見切れが出るとの報告があった。YouTubeの外枠自体の位置ずれとは区別する。

v1.2.1は外枠の左右安全余白を揃え、v1.2.2は外枠とプレーヤーのピクセル寸法を同期したが、実機での解消は確認できていない。追加修正を決め打ちせず、条件比較で原因候補を絞る。

## 開き方

通常Safariでは <https://youtube-kit.tokana2212.workers.dev/?lab=layout> を開く。PWAでは本体をv1.2.3に更新し、設定 → アプリとホーム画面 → 表示ずれの比較画面から開く。同一ウィンドウで移動するため、PWAの表示状態を保って比較できる。

既存の `?lab` の連続再生検証は残す。新画面は独立した診断画面で、Googleへのログインは不要。既定のサンプル、または明示入力した動画URL/IDの一件だけを再生する。通常の視聴キューや設定、認証、クラウド同期は読み書きしない。

## 最初に試す3条件

比較は同じ動画・同じ開始方向・同じ表示モードで行う。初めは通常表示のまま試す。サンプルでAの症状が出ない場合は、症状が出ている動画URLを入力する。

1. 縦向きでAを選び「1. この条件で準備・やり直し」→「2. 再生開始」。再生できなければ動画の下の「再開」を押す。
2. 縦表示の見え方を記録する。
3. 横へ回転し、操作バーと画面の動きが落ち着いたら見え方を記録する。「気づいた点」には黒帯の大きさや、停止中にも出るかなどを記載できる。
4. 横のままAを準備し直して開始し、最初から横向きの場合も記録する。
5. B、Dについても、縦からの回転と最初から横の場合を同じ手順で比較する。
6. 「3. 結果をまとめてコピー」で結果をこのチャットへ貼る。コピーできない場合は「コピー用の結果」から選択してコピーする。

各試行で条件を変えたら、必ず準備し直す。準備と再生開始は分けており、画面外での事前準備を含む本体の開始経路と比較できる。動画最大も調べる場合は、初めの通常表示を記録してから動画上部の最大化ボタンで切り替え、追加で記録する。

青い線は外枠の位置を示す。映像だけがずれているか、iframeや外枠ごとずれているかを区別する。可能なら症状の出た画面のスクリーンショットも結果と一緒に共有する。

記録ボタンまでスクロールするとSafariの操作バーが変化し、Aなどでは動画サイズも変わることがある。スクロールで症状が消える場合は、消える前のスクリーンショットを撮り、その変化をメモへ残す。結果には直近のサイズ変更履歴も含めるが、映像そのものは記録しない。

## 比較条件

全条件で本体のPlayerと公式YouTube IFrame APIを使い、初期条件は通常表示とする。Aを基準に、各条件は次の点だけを変更する。条件間の準備し直しはプレーヤーを再作成するが、試行中の回転やサイズ切替では再作成しない。

| 条件 | Aからの変更 | 注目点 |
|---|---|---|
| A | なし。自動調整・幅100%・画面外200×200px準備 | 現状の再現を確認する |
| B | 表示開始時の初回計算後、回転・操作バーへの寸法追従を止める | 回転後も枠の幅・高さが一定か。横で小さくても正常 |
| C | 高さから横幅を制限する処理を外し、横幅基準にする | 高さ基準への切り替えと関係するか。上下が画面外でもスクロール可能 |
| D | iframeの幅だけを0、最小幅・最大幅を100%にする | iframeのパーセント幅指定が関係するか |
| E | iframeの幅だけを外枠から継承するピクセル幅にする | パーセント指定を除いた場合の比較 |
| F | 画面外の事前準備を外し、再生開始時に表示位置で作成する | 200×200pxから移動・拡大する経路が関係するか。再生許可のため再開操作が必要な場合がある |
| G | 外枠の角丸とoverflow:hiddenを外す | 切り抜きや表示レイヤーとの関係。外へ映像がはみ出すか |

Bは通常・動画最大を切り替えると、そのモード開始時に一度サイズを計算し直す。その後の回転には追従しない。サイズ固定でもCSSの中央配置は維持する。

## 結果から分かる範囲

- Aで再現しBで回転後の症状が消えるなら、開始後の寸法変更が有力。ただしBのサイズが小さい影響もあるためCなどと合わせて確認する。
- D/Eだけ正常なら、iframeの幅指定方式が有力。
- Fだけ正常なら、事前準備の大きさや画面外からの移動が有力。
- Gだけ正常、または外枠の外に映像が見えるなら、切り抜き・描画レイヤーを優先して調べる。
- 回転後だけ異常で最初から横向きなら正常の場合、回転時の寸法更新や描画更新が有力。
- Aで症状が出ない場合、動画・通常画面のレイアウト・シアターの明るさフィルターなど、比較画面に含めていない条件が候補として残る。Aが再現しないまま他条件を正常と判定しても、原因を除外できない。
- 寸法が一致していても、iframe内の映像のずれを否定できない。クロスオリジンのため、映像内部の位置・寸法・DOMは読まない。

いずれも候補の絞り込みであり、単独の結果だけでSafariまたはYouTubeの不具合と断定しない。

## 記録と保存

版番号、実機の入力情報、User Agent、Safari/PWA、通常/最大化、開始時と記録時の向き、window/visualViewportの寸法・スクロール位置、外枠とiframeの矩形・CSS幅・幅高さ属性、サイズ計算とsetSize呼出しの直近120イベントを結果へ含める。

見え方は利用者が「正常」「右ずれ・左黒帯・右見切れ」「その他の異常」「再生できない」から選ぶ。結果は診断専用のlocalStorageキーへ保存し、自動送信しない。画面を開き直した場合は「前回保存した結果を読み込む」でコピーを再開できる。認証トークンやアカウント情報は記録しない。

## 検証境界と参照

開発環境では型検査・ビルド・差分確認・公開反映を確認する。iPhone上での再現と原因の判定は、利用者から返る比較結果を待つ。表示比較の各条件は診断画面限定であり、本体の通常動作は変更しない。

- [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference): 公式API・最低200×200px・サイズ指定。
- [WebKit #155198](https://bugs.webkit.org/show_bug.cgi?id=155198): 回転時のiframe寸法とmin/max幅の過去の回避策。修正済みの古い報告であり、今回の原因と同じとは確定していない。
