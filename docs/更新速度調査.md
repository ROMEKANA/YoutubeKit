# 登録チャンネル更新速度の調査

更新日: 2026-10-30

## 原因

- YouTube Data APIの `playlistItems.list` は `playlistId` を1つ指定する方式で、全登録チャンネルの新着を1回で取得する公開APIではない。
- 新着動画が3本だけでも、どのチャンネルに追加されたかを知るために各40チャンネルのアップロード再生リストを確認する必要がある。
- 従来は1チャンネルごとに「iPhoneからWorkerへの次ステップ要求→WorkerからYouTube APIへの要求」を待つ直列処理だった。40チャンネルでは端末とWorker間の往復も40回近く発生し、新着数に関係なく遅く見えていた。

## 対応

- 2回目以降の通常更新は、取得済みチャンネルを5件ずつ1ステップで並行確認する。
- 各チャンネルで見つかった新規動画IDを合わせ、`videos.list`の上限50 IDごとにまとめて詳細を取得する。
- 初回更新、明示的な過去分再取得、続きページが必要なチャンネルは、中断後の再開位置を保つため従来どおり1チャンネルずつ処理する。
- 個別チャンネルの一時的な失敗は記録して後続を続け、認証切れやAPI利用上限は更新全体を中断する従来の安全性を維持する。

40チャンネルがすべて通常更新の並行対象なら、ブラウザからの投稿確認ステップは約40回から約8回に減る。YouTube APIの投稿一覧要求自体は、取得漏れを避けるため各チャンネル分を維持する。
