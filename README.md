# YoutubeKit

自分で選んだYouTube動画だけをキューで観る、個人専用アプリの試作です。

現在のバージョンは **0.2.1**。React + TypeScript + Viteの画面に、Cloudflare Workers / Hono / D1とGoogle OAuthによる登録チャンネル取得を追加しました。

チャンネルの投稿一覧が取得できない場合は、そのチャンネルを飛ばして残りの取得を続けます。一覧と設定にチャンネル名・理由を表示し、更新で再試行できます。一部失敗時は更新の基準日時を維持します。認証切れ・権限不足・API利用上限では全体を中断します。
未設定のローカル環境では、これまでのサンプルモードで操作を試せます。
正式な要件は [SPEC.md](SPEC.md) を参照してください。

## 起動

Node.js 24 LTSを推奨します。プロジェクトのフォルダで次を実行してください。

```powershell
npm install
npm run dev
```

ブラウザで <http://127.0.0.1:5173/> を開きます。

依存関係が既にインストールされている場合は、`npm run dev` だけで起動できます。
停止する場合は、そのターミナルで `Ctrl+C` を押します。

## 実際の登録チャンネルを使う

Google CloudでYouTube Data API v3とWeb用OAuthクライアントを設定し、ローカルの `.dev.vars` にClient ID・Client Secret・許可メールアドレスを設定します。
暗号鍵は `npm run secrets:init` で、既存ファイルを上書きせずに準備できます。別のYouTube APIキーは不要です。

```powershell
npm run secrets:init
# .dev.vars を手元のエディターで編集してから進む
npm run db:migrate
npm run worker:dev
```

別のターミナルで `npm run dev` を起動し、設定からGoogleへ接続します。
ローカルのリダイレクトURIは `http://127.0.0.1:5173/auth/callback` です。
**詳しい画面操作・設定値・本番配備・エラー対処は [セットアップ手順](docs/セットアップ.md) を参照してください。**

通常の更新は、前回成功した更新の開始日時以降を中心に取得します。基準日時はD1を正としてブラウザにも控え、失敗時には進めません。
過去分を取り直す場合だけ、設定の「登録チャンネルと過去分を再取得」を使います。

## 操作

1. 一覧のサムネイルをタップするとキューに追加され、再生順の番号が表示されます。サムネイルや右端の番号をもう一度押すと削除されます。
2. 画面下のキュー概要を押すと、順序を確認できます。
3. キューは左のハンドルをドラッグ、または上下ボタンで並べ替えられます。
4. 「再生開始」を押すと、1つのYouTube公式プレーヤーでキューを再生します。
5. キューの最終動画で終了します。保存済みキューは再生後も残ります。

タイトルなどサムネイル以外の領域を押すと、動画の非表示・復元などのメニューを開きます。
ヘッダーの目のボタンで非表示動画も表示できます。歯車の設定では、表示密度（10〜200%、10%刻み）、表示件数、短い動画の除外時間（分単位、初期値3分）を変更できます。
表示密度は100%が標準で、大きくすると画像・文字・行余白が広がります。小さい倍率でも操作領域と文字には最小サイズを設けています。
「さらに表示」を試す場合は、設定の初回表示件数を2件などへ変更してください。

## この試作でできること

- サムネイル画像の表示とタップによるキュー追加
- 重複防止、再生順番号の表示、再タップでの削除
- キューの並べ替え、個別削除、全削除、本数・合計時間の表示
- キュー、非表示状態、設定のブラウザ内保存と再読み込み時の復元
- チャンネル絞り込み、非表示・復元、表示密度、手動ページング
- YouTube IFrame Player APIによる選択キューの連続再生
- 読み込み・埋め込みエラーの表示、再接続、自動再生が阻止された場合の再開操作
- 別画面へ移ったときの一時停止
- Google OAuth接続、許可アカウントの制限、再接続、ログアウト、接続解除
- 登録チャンネルの全ページ取得、アップロード一覧経由の新着同期、D1への保存
- 更新日時による差分取得、同期進捗表示、中断後の再開
- 実アカウントのサムネイル・チャンネルアイコン表示

## 現在の制約

- Google未設定のローカル環境は `public/demo-videos.json` のサンプル表示です。この場合の更新ボタンはサンプルを再読み込みします。
- サンプルのタイトル・日付・再生時間は手入力・概算で、アイコンは仮表示です。実接続後はAPIの値と画像URLを使います。
- 動画情報と認証情報はD1、キュー・非表示・表示設定はブラウザの `localStorage` です。後者は端末間で同期しません。
- サンプルと実アカウントの保存領域は分離しています。サンプルキューを実チャンネルへ無断で混在させません。
- 初回と過去分の再取得は、初期値で各チャンネル100本までです。通常更新は前回日時まで取得し、画面は最新1000本までを対象にします。設定可能な範囲はセットアップ手順を参照してください。
- ブラウザのサイトデータを消すと、保存キューと設定も消えます。
- 実Googleアカウントの認証・登録チャンネル取得とCloudflare本番環境は未検証です。自動検証ではGoogle応答を置き換え、ローカルのWorkersとD1で処理を確認しています。
- Manifest、Service Worker、ホーム画面からの独立起動、オフライン起動、アプリ更新通知は未実装です。
- バックグラウンド再生用の機能はありません。アプリ側は画面が非表示になったときにプレーヤーを一時停止します。
- YouTube公式プレーヤーの広告、関連動画リンク、標準操作はそのまま表示されます。プレーヤー内の利用者操作まで禁止する仕組みではありません。
- Shortsだけを確実に識別する公開API項目は確認できなかったため、初期値3分以下の時間フィルターを使います。通常の短い動画も除外されます。調査内容は [Shorts除外調査](docs/Shorts除外調査.md) を参照してください。
- iPhone Safari、iPad、ホーム画面PWA、PiP、画面ロック時の挙動は実機未検証です。

## 再生の技術検証

<http://127.0.0.1:5173/?lab> に専用ページがあります。保存済みキューには影響しません。

1. 「検証キューを再生」を押します。
2. 再生が始まったら「終了10秒前へ（検証用）」を押します。
3. 1本目の終了後に2本目が自動再生されるか確認します。
4. 2本目でも終了10秒前へ移動し、最後で「選んだ動画の再生が終わりました。」と表示されるか確認します。
5. さらに15秒程度待ち、3本目や先頭動画が自動再生されないか確認します。

このボタンは `seekTo()` を使って終了付近へ移動します。時間を偽って完了を発火させるものではありません。
検証結果と参照資料は [技術検証レポート](docs/技術検証レポート.md) に記録します。

## ビルドとテスト

```powershell
npm run build
npm test
npm run worker:check
npm run test:worker
npm run preview
```

`build` は型検査後に `dist/` を生成します。`preview` は <http://127.0.0.1:4173/> です。
`npm test` は重複防止、並べ替え、保存データ復元、破損データへの対応、終了イベントなどを検証します。
`npm run test:worker` はローカルWorkers/D1上で、認証検証、CSRF、登録チャンネルのページング、日時による差分同期、失敗時の保存保持、再開を確認します。実GoogleアカウントやCloudflare本番には接続しません。

## iPhoneでの操作確認

PCの `127.0.0.1` はiPhoneからは開けません。ローカルネットワークでの試用には、同じWi-Fiへ接続したうえで次の手順を使えます。

1. PCで通常の開発サーバーを `Ctrl+C` で停止します。
2. `npm run dev -- --host 0.0.0.0` を実行します。
3. 表示された `Network` のURL（例: `http://192.168.x.x:5173/`）をiPhoneのSafariで開きます。
4. Windowsのファイアウォール確認が出た場合は、利用中のプライベートネットワーク内だけでの接続可否を自分で判断してください。

この操作は開発サーバーを同じネットワーク内へ公開します。信頼できる自宅などのネットワークで試してください。
HTTP接続はUIの試用向けです。PWA、OAuth、本番相当のiOS再生確認にはHTTPS環境を準備する必要があります。
外部へのデプロイやクラウド設定は、この試作では行っていません。
